# Five real agents: live break-and-recover pilot, 2026-10-24

We ran five independent tool-using model sessions against a shared dispatch
workspace, interrupted the work after two real SQLite executions, and measured
whether the remaining work completed correctly. The experiment produced genuine
failures, successful recoveries, and unresolved attempts. **It did not demonstrate
an LGGR advantage over ordinary complete-contract checking.**

## What ran

Workers 0 and 3 used GPT-4o-mini, workers 1 and 4 Claude Haiku 4.5, and worker 2
Gemini 2.5 Flash Lite, through OpenRouter. Each had a separate persistent history
and could inspect the board, calculate line-item totals, propose its own allocation,
or escalate. A serial scheduler controlled tool turns; this was not a concurrent
race test. Model responses caused actual tool calls and SQLite transactions.
No model-generated code executed, and no satisfying resource assignment was fed
to agents. The exact matching oracle remained outside the agent interface.

Each seed first ran all five agents to establish a shared working state. Two jobs
then executed. A feasible resource withdrawal, an impossible capacity reduction,
or no change followed. Three arms forked the **same state and live histories**:
A received generic retry feedback, B received complete conventional validation
findings, and C received the same findings plus LGGR receipts. All arms used the
same safety gate, models, tools, and two-pass recovery limit.

## One concrete recovery, and its counterexample

In seed 4101, workers 0 and 1 had already executed totals 835 and 1270 cents in
slots 0 and 2. Worker 2 held slot 1 for its 852-cent job. The host withdrew slot 1
and advanced the epoch. All five local proposal checks still passed, while the
combined plan failed resource/freshness checks. The LGGR fiber receipt recorded
that the local report was insufficient, and the resource monitor detected the
occupied unavailable slot.

In arm C, the remaining workers proposed slots 6, 5, and 4 at the new epoch, with
totals 852, 1064, and 1252. Those proposals passed the independent judge and were
actually executed. The two earlier rows remained byte-for-value unchanged.
The other arms did not recover that seed. **On seed 4102, the opposite happened:**
A and B recovered while C remained blocked. Both observations are retained.

The first development run is also retained: it failed before any intervention
because GPT-4o-mini repeatedly submitted incorrect arithmetic (32 calls,
$0.04562550). A calculator tool was added equally to all arms before evaluation.
The second development run cost $0.10133122; B and C recovered, while A remained
blocked. Development results are not included in the held-out table.

## What this supports

The pilot demonstrates a working five-agent integration, locally valid proposals
that become globally invalid during execution, preservation of completed work,
and some real model-driven recovery. It also demonstrates failures of recovery
and of explicit escalation despite an available escalation tool.

The C adapter packages conventional findings into fiber/resource certificates;
it does not implement an autonomous repair solver or expose the matching oracle.
The outcome ties and higher observed C dollar cost support **no superiority
claim**. There are only two seeds per condition, three model families, a fixed
serial scheduler, and synthetic injected disruptions. Natural failure rates,
parallel races, larger workflows, and general convergence remain untested.
No new theorem or broad reliability guarantee follows from this pilot.

A further study should preregister a larger paired set, include naturally arising
faults and independent task families, and give both B and C any added solver or
feasibility capability. Negative outcomes should remain published rather than
being tuned away after observing evaluation seeds.
