ASSESSMENT

The central mathematical development survives this source review. In particular,
the finite real primal/dual attainment proof constructs its witness through
separation, rather than assuming zero gap. The program's accepted-outcome
theorems connect independently checked rational constraints to real-variable
semantics. The manuscript correctly distinguishes these results from general
Python refinement, unbudgeted simplex completeness, empirical confidence,
authentication, action safety and consciousness.

Three reproducible engineering issues remain, all rated P2 (ordinary priority).
They affect checker usability and reproducibility tooling; none is a demonstrated
false contextuality verdict or false mathematical theorem. Correct them before
claiming that the documented verification/rebuild workflow is portable and
repeatable. This is a favorable mathematical source review with bounded execution
evidence, not a fresh independent Lean compilation or publication authorization.

FINDING 1 — Optimal certificate replay rejects the solver's valid integer inputs

Location: code/contextuality_lp.py:116-130; compare 66-74 and 133-149.

Reproducer:
    cert = solve_standard([1], [[1]], [1])
    verify_standard([1], [[1]], [1], cert)  # False
    verify_standard([Q(1)], [[Q(1)]], [Q(1)], cert)  # True

The solver explicitly accepts int and Fraction data and normalizes them. The
optimal checker instead requires every original problem value to already have
exact type Fraction. Thus replay against unchanged, valid original integer input
fails. The two new infeasibility/unboundedness checkers accept the same integer
data by using _certificate_inputs, so the three outcome APIs are inconsistent.

The optimal checker also raises AttributeError on a None certificate instead of
returning False. verify_defect similarly lacks a complete malformed-certificate
boundary; verify_observed compensates by catching those exceptions. These are
boundary failures, not evidence that valid certificates prove wrong optima.

Repair: use _certificate_inputs at the optimal replay boundary; validate the
certificate and vector shapes before attribute access; handle ordinary malformed
inputs consistently with verify_infeasible and verify_unbounded. State whether
pivot metadata is validated as schema data or ignored as nonmathematical metadata.
Add integer-input round trips and malformed-certificate cases for the old checker.

FINDING 2 — Full-census check mutates a byte-sealed file on Linux

Location: tools/replay_full_axiom_census.py:45, and its check path at 82-86.
Affected artifact: lean4/FullCensus.lean.

replay(root, check=True) unconditionally regenerates FullCensus.lean with
write_text before running Lean. At the pinned commit this tracked file has CRLF
line endings and is covered by both release manifests. On Linux the write uses
LF, changing 995 bytes into 968 bytes without changing the Lean text.

Before SHA-256:
349585121114da9febd30dc835b7acdece5d2951b55510e12dedd5bb14fe763e
After SHA-256:
24962b5ad8cd1d986f2fe8d67908edca3883103f7f1bb112ee08128afc8f3187

The isolated Python orchestration probe returns success against the stored
796-declaration transcript while leaving the file changed. That probe mocks the
Lean subprocess solely to isolate Python write behavior; it does not establish
fresh Lean validity. The unconditional write occurs even before a missing/failing
Lean executable can be detected.

This invalidates subsequent manifest verification. verify_deposit checks manifests
before invoking its Lean checks and does not repeat the manifest check afterward,
so a successful proof replay could finish after altering a sealed input. The
package's -text Git attribute deliberately preserves original bytes; ordinary
checkout conversion is not the cause.

Repair: make --check read-only. Compare the expected generated text with the
existing source and run that source, or use a temporary census file outside the
sealed tree. Reserve source generation for an explicit write mode. Add a check
that every sealed byte remains unchanged after the full verification command.

FINDING 3 — Later-day release refresh creates an archive it rejects

Location: tools/rebuild_release.py:151-152, 163-186, 265-270 and 323-325.

The refresh command chooses today's date for the new ZIP but leaves
zenodo_metadata.json publication_date unchanged. Validation requires those dates
to agree. The documented command therefore fails when rerun after the release day.

An isolated minimal release fixture retaining the deposited publication date
2026-10-21, refreshed on 2026-10-23, produces paper_2026-10-23.zip and then reports:
    metadata publication_date differs from release ZIP date

In the real flow, refresh also removes a differently dated previous ZIP before
main validates the replacement. Thus a failed refresh can already have replaced
the prior release envelope. This finding comes from executing the unchanged
release functions on a temporary fixture; the repository release was not changed.

Repair: distinguish reproducing a pinned release from creating a new release.
For reproduction, derive both archive name and timestamps from the pinned release
date. For a new release, update date-bearing metadata deliberately and consistently.
Validate the staged new envelope before removing the previous ZIP. Add a regression
check that rebuilds the same release on a later calendar date.

MATHEMATICAL AND LEAN ASSESSMENT

1. Attainment and the contextuality alternative

ContextualDuality.lean:44-94 proves compact convex distance duality with the
nearest point and functional both existentially constructed. The nonzero-distance
case separates the open ball from the compact convex set, extends the bound to
the closed ball, and normalizes the separating functional by its operator norm.
The zero-distance case uses the zero functional. This is the substantive step
that prevents circular reliance on a supplied zero-gap certificate.

contextuality_strong_duality at 175-209 applies this to the finite simplex image
in PiLp 1. Nonempty G is explicit, so an empty simplex is not silently treated as
feasible. Coordinate evaluation supplies the infinity-norm-bounded dual vector.
joint_or_positive_dual, positive_dual_excludes_joint and cost_zero_iff establish
existence, positivity and exclusivity. canonical_dual_attainment at 327-336
constructs an actual maximizing deterministic column. I found no missing premise
or reversed inequality in these arguments.

The theorem is more general than the contextuality application: it accepts any
finite real column family and target. Compatibility is a condition for the
empirical-model interpretation, not an ingredient smuggled into convex duality.

2. Rational and real semantics

Weak duality is genuinely algebraic over the declared ordered field. Rational
certificates are embedded into the reals to bound all real competitors. The
standard-form slack inequalities and exact slack construction have the correct
sign convention for Ap-u+v=e. Five concrete numerical certificates replay and
their generated Lean source agrees with the stored fixture data.

General real attainment is not a constructive proof of rational-witness search
termination. The manuscript does not claim that it is. General rational attainment
as a separate constructive result, unbudgeted completeness and universal Python
refinement remain distinct possible extensions, not identified defects here.

3. Executable simplex and certified outcomes

Simplex.solve_correct and CertifiedOutcomes.solve_certified_correct rely on the
mandatory final validity predicate. This is a legitimate checked-result design:
the separate weak-duality/Farkas/ray theorems give that predicate mathematical
meaning. It does not require the search phase itself to have a complete invariant
proof. A faulty search may refuse or fail to find a witness; it cannot acquire a
Lean theorem of validity merely by extracting a tableau candidate.

infeasible_excludes_real checks A^T y >= 0 and b^T y < 0 against the original
rational data, then rules out all real feasible points. Unboundedness correctly
requires both a feasible base and a nonnegative nullspace direction with strictly
negative objective. unbounded_below_real constructs a point below every real
objective floor. A direction alone is not mistaken for a feasibility proof.

The recursions are structurally budgeted. There is explicit accounting for the
optimal-only execution and search accounting for the extended outcomes. Finite
pivot termination is not a wall-clock/bit-complexity bound. Current documentation
states this accurately. No full theorem of Python/Lean program equivalence was
found or represented as completed.

4. Observation, error and authority claims

Bridge's induction proves fiber preservation under common finite update words.
The extension to a deterministic controller reading only the common transcript
is a valid prose induction under the stated common-policy premise. It does not
cover private side channels or arbitrary changed report maps.

ErrorBudget correctly uses actual one-step defects. The uncertainty-adjusted
witness bound is a direct norm perturbation bound, with the raw sum over all
context/outcome entries. The noisy-observation API preserves signalling samples
and does not infer classicality from a zero adjusted margin. Continuous ODE
enclosures and the hybrid comparison argument remain supplied mathematical
premises/prose rather than claimed Lean ODE verification.

MindContracts' whole-fiber maximality and score regret/gap results have the
necessary hypotheses. A large error upper bound is correctly separated from
actual error. There is no formal consciousness conclusion.

The ledger and three-role modules are simple models, and some facts are
definitional (especially the one-constructor authority-effect type). The current
manuscript explicitly calls them policy/model results. They are not an ASI or
intelligence impossibility theorem. The package's stronger claims rest on the
duality and certificate mathematics, not the number of labels or declarations.

DOCUMENTATION RECOMMENDATIONS

Keep the current separation of formal, exact computation, mathematical argument,
imported theorem and policy. It prevents the central conceptual overreach this
project previously risked. In the paper's opening, emphasize the reproducible
certificate pipeline and the exact boundary of what each check establishes.

Several inherited module header comments still refer to older manuscript status
(for example ResultII's temporal-privacy OPEN label). The README explains that
these files are preserved byte-for-byte. A short current-scope note outside the
preserved modules would make navigation easier without rewriting historical
evidence. This is editorial cleanup, not an additional correctness finding.

Avoid using theorem counts as measures of novelty or depth. The material includes
substantial formal convex analysis alongside short policy and factorization
lemmas. The count is useful for coverage accounting only. A literature/priority
review was not part of this audit; no first-in-literature conclusion is supplied.

REVIEW BUNDLE

independent_review.py contains the independent LP tests and minimal reproducers.
Run it with:
    python independent_review.py /path/to/package independent_results.json
SciPy is required for the additional numerical cross-check. The reviewed package
itself still uses only standard-library exact arithmetic for its solver.

The census write probe explicitly mocks the Lean subprocess and must not be
reported as a Lean proof replay. The release date probe is intentionally sensitive
to the current date and demonstrates the bug on dates after 2026-10-21.

independent_results.json records this run. verification.json summarizes the
review checks and their limits. source_inventory.json binds the materialized
source files to byte hashes. SHA256SUMS binds the review bundle itself.
